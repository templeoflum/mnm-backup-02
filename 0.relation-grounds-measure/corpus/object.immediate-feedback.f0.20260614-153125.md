**statement (plain)** — the learnable-programming / immediate-feedback principle: people understand what they can see, so a learning environment must make the otherwise-invisible visible — show the data, make program flow visible — and respond immediately, so the learner can react to a work in progress instead of holding the whole model in their head.

**statement** — Victor: "People understand what they can see. If a programmer cannot see what a program is doing, she can't understand it." The "number one thing you can do" is **"show the data."** Live coding alone is insufficient because the programmer "must type at least a full line of code before seeing any effect," still doing the creative work in her head; the environment must instead provide "an external imagination where the programmer can always be reacting to a work-in-progress." **[confirmed]**

**basis** — the same active-reading premise as the [[object.explorable-explanation]], turned toward learning to program: visibility plus a tight feedback loop replaces invisible symbol manipulation. The immediate-update loop is what makes the other learnable-programming techniques (scrubbing time, following flow, seeing state) possible. **[confirmed]**

**lineage** — stated by **Bret Victor** in "Learnable Programming" (September 2012) [[source.victor-2012]] **[confirmed]**, a companion to his 2011 explorable-explanations program [[source.victor-2011]]. Roots in Alan Kay / Seymour Papert constructionist learning environments. **[confirmed as attribution]**
