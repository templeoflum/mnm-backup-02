## the pinning — worked out

The two groups still at `00` were assigned in f1 only to a *group* (sources → the `00/01/02` reference-leaf trio; measuring objects → `0`'s cells), with the per-record pin deferred. Working it out surfaces one honest finding:

**There is no deterministic signal for the pin.** A source carries `kind:` (261 paper · 229 book · 14 standard · long tail) and a measuring object carries `essence:` + `field:` — but *which reference-leaf* a source serves (anchoring `00` / calibration `01` / measurement-standard `02`) and *which cell* an object verb-anchors to are **readings**, not lookups. `kind:` does not map to role — a book or paper can play any of the three roles. So the pin is per-record judgment across **790 records**, and the rule itself was still listed open in `corpus.index` ("source sub-sort within a canon-leaf").

**Proposed first-pass rule (a hold, for the operator's read before any move):**

- **sources → reference leaves.** Default rest is **`00`** (`constant·references·flux` — the anchoring reference), which is where they already sit and is a *valid* home; the leaf is not a misfit. Pin *off* `00` only where a source clearly plays a sharper role: a **measurement-standard / handbook / normative spec** (e.g. the 14 `kind: standard`, NBS handbook, ACM/IEEE/ISO) → **`02`** (`magnitude·measures·number`) or its `010 standard·sets·zero` cell; a **calibration/method source** (how a measure is gauged) → **`01`** (`gauge·calibrates·accuracy`).
