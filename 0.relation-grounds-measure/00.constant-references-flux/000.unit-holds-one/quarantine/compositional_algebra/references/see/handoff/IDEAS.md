# Ideas

The posture: speculation. What might be worth doing that hasn't been decided on yet.

Distinct from neighbors:
- **[../ROADMAP.md](../ROADMAP.md)** — direction the project *has* decided on (at various horizons)
- **QUEUE.md** — pending work the project *is* picking up
- **OPEN_QUESTIONS.md** — uncertainties about specific decisions
- **OBSERVATIONS.md** — patterns noticed in current work

An idea sits here while it's being considered. When it matures, it gets *acted on*:
- **Adopted:** becomes a ROADMAP entry (medium/long-term) or QUEUE item (immediate); or becomes its own project under `../projects/`. Removed from this file.
- **Rejected:** dropped from this file. The rejection may produce a CHARTER entry if it's a refusal worth committing to.
- **Deferred:** stays here with a note about what it's waiting on.

The pruning rule: ideas that have been here for a long time without movement either get decided on or get dropped. No "interesting forever" status.

## How to write an entry

Each entry has:

- **Date proposed** — `YYYY-MM-DD`
- **The idea** — what it is, in 1-3 sentences
- **What problem it would address** — why it might be worth doing
- **Relationship to existing work** — how it interacts with the framework, current projects, current roadmap
- **What it would cost** — rough estimate (session-count, complexity, irreversibility)
- **Status** — Proposed / Under discussion / Deferred (with reason) / Adopted (with destination) / Rejected (with reason)

Keep entries scannable. The point is to surface possibilities, not to pre-design them.

Example shape:

```
### 2026-05-27 — idea title

**The idea:** [1-3 sentences]

**What problem it would address:** [1-2 sentences]

**Relationship to existing work:** [where it would fit; what it would touch]

**Cost:** [rough estimate]

**Status:** Proposed
```
