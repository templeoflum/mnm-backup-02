# see/

The framework's **Layer 1**: ways of looking. Postures from which the work is viewed.

A master craftsman looks at their work from many angles before, during, and after making it. Each angle is a *posture* — a stance the operator takes that shapes what they perceive. The framework gives each posture its own surface so the stance can be entered deliberately rather than incidentally.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the see/know/do model in full.

## How to add a posture

A posture earns a file when:

1. It induces a *distinct cognitive stance* not already covered by another posture document.
2. It would produce different content than any existing posture would for the same subject matter.
3. It has at least one concrete moment where the absence of the posture was felt.

The shape of a posture document: orient the reader to the stance, describe what gets written from it, point at related postures. The contents follow naturally from being in the stance.

See [`../know/disciplines/posture_naming.md`](../know/disciplines/posture_naming.md) for the discipline that governs naming.

## How postures relate to each other

The postures complement rather than overlap:

- **SURVEY** is wide; **CHARTER** is bounded (refusals); **CRITIQUE** is honest (gaps).
- **LINEAGE** looks backward; **ROADMAP** looks forward; **DEV_LOG** is the chronological substrate they reference.
- **ARCHITECTURE** is the meta-posture — it describes the relationship between all the others.
- **handoff/** captures the *current* state from each posture (snapshot, queue, uncertainties, patterns, ideas).

A complete look at the project rotates through several postures. No single document gives the full picture.
