## source 1 — `extract.miroglyph.f0.20260706-153052.md`
path: `0.relation-grounds-measure/00.constant-references-flux/000.unit-holds-one/quarantine/mythmaking/miroglyph/`

UNVETTED (prior-project quarantine). Self-described as "the deep pass on the vein's anchor" and a reconciliation of "4-5" prior operator designs. Attributed to keeper, composted 20260706-153052.

What the source says:
- It describes miroglyph in plain terms as a "navigation topology for mythic transformation" — a "fixed skeleton of positions you move through to structure a journey," in any medium (story / ritual / divination / game / performance). It quotes the motto *"Myth is not discovered, it is navigated,"* and calls it "structure without prescription."
- It describes a skeleton it says is "stable across every version": **19 points** = **18 nodes (3 arcs × 6 conditions) + 1 center**.
  - The "3 arcs" (thematic modes): "Descent/Shadow (D)," "Resonance/Mirror (R)," "Emergence/Mythogenesis (E)."
  - The "6 conditions" (phases): "Dawn/Initiation," "Immersion/Encounter," "Crucible/Crisis," "Alignment/Harmony," "Unveiling/Wisdom," "Return/Integration."
  - The center: "Nontion (∅)" — "the pause/reset; integration-in-absence; traversable but not a node."
- It says each node carries "dual naming (functional + evocative)," a code (D1…E6), a title (its example: "D1 = The Catalyst Shard"), plus role and tone.
- It describes relationships that "make structure visible": "polarity pairs" (conditions 1↔4, 2↔5, 3↔6), "condition-resonance" (D1/R1/E1 sharing initiation across arcs), and an optional "motif/evidence-marker" system (6 categories O/A/Q/B/F/M; primary locked by condition, secondary by arc).
- It says the topology is "Fractal" — "the same topology nests at any scale (beat ⊂ scene ⊂ chapter ⊂ book)."
- It presents what it calls "the crux": one skeleton, **TWO realizations** it says are unreconciled — an "Authoring map" (v4 / mythic-library) vs a "Physics engine" (mythos / Temple-of-Lum). The source tabulates the difference: the "3" as narrative *arcs* (Descent/Resonance/Emergence) vs interaction *lenses* / verbs ("Fracture · Echo · Fusion"); the "6" as narrative *conditions* (Dawn…Return) vs *pressures* / forces ("Threshold · Gravity · Friction · Resonance · Tension · Silence," 0–1 per node); a "static map" you author vs a "dynamical system" that accumulates pressure, detects patterns ("4 captures, fluidity, avoidance") and "perturbs the topology"; Nontion as "the pause" vs "the fluidity metric itself"; artifact as "path library" vs "behavioral snapshots." It states these are "not contradictory" (the engine spec calls its nodes "training wheels" on the same skeleton) but that the semantics differ.
- It records a decision it attributes to the operator (20260706): "both — layered. The map is the keystone, the engine is the terrain." — ground the "authoring-topology first," defer the physics engine.
- It frames "mythOS" as a **7-layer stack** miroglyph lives in: "1. Mythic Library · 2. ACP · 3. MiroForge · 4. MiroGlyph (this) · 5. Narrator Protocol · 6. Artifice · 7. Experience." (Note: source 2 explicitly retracts this framing — see below.)
- It gives a lineage v1→v4 ("prescriptive → topological"): v1 Traversal Grid → v2 Architecture Primer → v3 Narrative Architecture → v4 Minimal Core. It names large lore docs, chiefly "Filamentum Miroglyphica (76KB, the fullest)."
- Honesty caveats it states itself: "v4 is the mature core," "Two realizations sit unreconciled," "All code is husk" (the JS app + Godot engine, neither trusted nor carried).
