## Schema notes (floating — shape of future manifests)

A manifest at 201 should always contain:
1. File inventory — every file at every address, type, status, where it belongs
2. Feature inventory — what each view/tool does, what works, what's broken
3. State snapshot — settled, floating, blocked
4. Intake/outflow ledger — what moved, when, confirmed
5. Schema notes — how the manifest itself should evolve

Open questions for the schema:
- Should the manifest track dependencies between files? Or is that the dependency system's job (Chunk D)?
- Should the manifest carry research inventory separately, or fold it into the file inventory?
- How does the manifest relate to checkpoints? Is a checkpoint just a frozen manifest?
- When does a manifest entry get retired vs preserved?
