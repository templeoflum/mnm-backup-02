# note — leaf model & page naming — f0

Captured mid-design (operator 20260630), refining slice 14 (page types). Not yet built.

## LOCKED — the leaf model

A zine is a stack of **leaves**, each leaf has **two sides**. Paper has two sides, so you
**add/remove leaves (pairs), never single pages** — a front + back stay married. Default =
**2 cover leaves** (= the 4 cover surfaces). Adding a leaf inserts a 2-side pair between the
inside covers. This also de-clutters nav: the strip shows **one chip per leaf**, not per side.
(operator: "everything is leaves with two sides, that's locked.")

## OPEN — the naming convention (the sticking point)

Operator **rejects** the publishing-standard spelled-out terms — "front cover / inside front
cover / inside back cover / back cover" — as **bulky & disjointed (3 words is too many)**. Wants
covers differentiated in **1–2 words**, and a scheme whose **look · sound · pronunciation cohere**.

Floated, not settled:
- `Fa Fb` (front-cover leaf, sides a/b) · `Ba Bb` (back-cover leaf) · interior `L1a L1b L2a L2b…`
- **The tension that breaks it:** **leaf numbers ≠ page numbers** (a leaf = 2 pages), so `L2` vs
  "page 3/4" reads confusingly. Numbering the leaves and numbering the pages collide.

Unresolved knots to settle next:
1. cover side-labels in ≤2 words (replace FC/IFC/IBC/BC).
2. interior: number by **leaf** or by **page** — and reconcile so they don't collide.
3. one suffix for "which side" (a/b · f/b · ·1/·2) that reads + sounds clean across covers AND interior.

Prior proposal (one option, not chosen): keep surfaces named, F/B = nav axis only, leaves group
them ⟨FC·IFC⟩⟨1·2⟩…⟨IBC·BC⟩. Operator wants something **leaner** than this.
